# Norse.Identity.Web.Server

The explicit-write `NorseUserStore` (Identity's store interfaces implemented directly, with no EF change tracker), `NorseUserManager`, `NorseSignInManager`, the `SignInManager` `.Outcome` view, and `ErasureService` over the entity model and `NorseIdentityDbContext` that `Norse.Identity.EntityFramework` carries — plus, since PR #27, `IAuthenticationService`'s gRPC implementation over that store, `Account/AccountService`, the account core's `IAccountService` implementation, and Train 3's `TwoFactor/TwoFactorService`, `Passkeys/PasskeyService` and `SignInMethods/SignInMethodsService` (`ITwoFactorService`, `IPasskeyService`, `ISignInMethodsService`). The thirty-five commands — `LoginCommand`/`RegisterCommand`/`EmailExistsCommand`/`LogoutCommand` and the anonymous tier's `TwoFactorSignInCommand`/`RecoveryCodeSignInCommand`/`ForgotPasswordCommand`/`ResetPasswordCommand`/`ConfirmEmailCommand`/`ConfirmEmailChangeCommand`/`ResendEmailConfirmationCommand`, and the account core's `GetAccountStatusCommand`/`SetPhoneNumberCommand`/`ChangeEmailCommand`/`ChangePasswordCommand`/`SetPasswordCommand`/`GetExternalLoginsCommand`/`RemoveExternalLoginCommand`/`DeletePersonalDataCommand`, two-factor's `GetAuthenticatorSetupCommand`/`EnableAuthenticatorCommand`/`ResetAuthenticatorCommand`/`DisableTwoFactorCommand`/`ForgetTwoFactorClientCommand`/`GenerateRecoveryCodesCommand`/`RevealRecoveryCodesCommand`, passkeys' `GetPasskeysCommand`/`GetPasskeyCommand`/`GetPasskeyCreationOptionsCommand`/`AddPasskeyCommand`/`RenamePasskeyCommand`/`RemovePasskeyCommand`, and the sign-in methods' `GetSignInMethodsCommand`/`GetPasskeyRequestOptionsCommand`/`PasskeySignInCommand` — wrap Heimdall's pure wire DTOs (Asgard's `CommandRequest<TRequest,TResponse>`) to give them mediator identity and an `[Authorize]` policy the wire records themselves never carry; handlers work entirely in `Outcome<T>` (Asgard's mediator law), reach Identity and OpenIddict only through the `.Outcome` views (`Norse.Identity.Outcomes`, plus the `SignInManager` view here), and return the exact wire result type directly — each service is a bare hydrate-and-send forwarder, no mapping switches. `AddNorseAuthenticationService(connectionString)` is the single composition-root entry point a host calls to pull in the `DbContext`, ASP.NET Core Identity (with the `NorseSignInManager` override), the generated mediator handler/validator-adapter/dispatch registration, and the services themselves.

Always runs inside an HTTP context, bound into Yggdrasil's `Hosting.Web.Server` process — never referenced from WASM or MAUI. Its HTTP surface is the external-login GETs (`MapNorseExternalLoginEndpoints`: the sign-in start `/Account/PerformExternalLogin`, and the link start `/Account/Manage/LinkExternalLogin` with its callback, both starts failing closed on Fetch Metadata) and one Razor page, the static-SSR external-login callback at `/Account/ExternalLogin` (`ExternalLogin/ExternalLoginCallback.razor`). The original Yggdrasil-scaffolded Razor page tree (`Components/`) is gone: its pages were replaced by gRPC operations on the services above and are served by Heimdall's `AuthN.Components`/`AuthN.Components.FluentUI`.

Part of the [Norse Architecture](https://github.com/NorseArchitecture) platform.
